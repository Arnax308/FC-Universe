# 📚 Existing Projects & Repositories

## 1. [GioAc96/fc-cm-web-parser](https://github.com/GioAc96/fc-cm-web-parser?utm_source=chatgpt.com)
**Purpose**

* Browser-based parser for FC 25 Career Mode save files.

**Tech**

* TypeScript
* Runs completely client-side
* No server required

**What it extracts**

* Player data
* Overall
* Potential
* PlayStyles
* Positions
* Clubs
* Contracts
* Attributes

**Why it's important**
This is probably your **best starting point**. Instead of reverse-engineering the save format yourself, adapt this parser to FC 26 if necessary. The author also mentions that the save format has remained fairly stable across recent FIFA/FC titles. ([Reddit][1])

---

## 2. [sammygriffiths/fifa-career-save-parser](https://github.com/sammygriffiths/fifa-career-save-parser?utm_source=chatgpt.com) 

**Purpose**

* Low-level parser for FIFA career save files.

**Language**

* JavaScript / Node.js

**Why it's important**
This is the parser that many later projects build upon. It decodes the binary save file into structured databases and tables, making it invaluable if you need to understand EA's save format. ([Skypack][2])

---

## 3. [xAranaktu GitHub](https://github.com/xAranaktu?utm_source=chatgpt.com)

Probably the most well-known reverse engineer in the FIFA modding community.

He has worked on:

* FIFA Live Editor
* Database reverse engineering
* Save format research
* Career Mode tools

If you hit a wall with parsing, chances are he's already solved something similar.

---

## 4. [SirSpacePirate/fc-tracker](https://github.com/SirSpacePirate/fc-tracker?utm_source=chatgpt.com) 

A passion project very similar in spirit.

Features include:

* Automatic save parsing
* Offline tracker
* HTML GUI
* Converts saves into its own internal format

The key takeaway is the architecture: **parse once → convert into your own schema → build everything on top of that**. ([Reddit][3])

---

## 5. [CMTracker](https://cmtracker.net?utm_source=chatgpt.com) 

Probably the biggest existing Career Mode companion.

Features:

* Player scouting
* Career statistics
* Save uploads
* Player database
* Squad analysis

Useful for inspiration, but your vision goes beyond it by focusing on long-term historical archives instead of just exposing the current save. ([Electronic Arts Inc.][4])

# What to Study First

If I were prioritizing your learning and implementation, I'd go in this order:

1. **GioAc96/fc-cm-web-parser** – understand how it reads and parses saves.
2. **sammygriffiths/fifa-career-save-parser** – learn the underlying binary format and data structures.
3. **xAranaktu's work** – reference for reverse engineering and EA internals.
4. **SirSpacePirate/fc-tracker** – study how they convert parsed data into an application-friendly format.
5. Build your own import pipeline and database.

## One architectural suggestion

Don't make the parser directly populate your database. Instead, introduce a neutral intermediate representation:

```text
FC Save File
      │
      ▼
Save Parser
      │
      ▼
Normalized JSON
      │
      ▼
Import Engine
      │
      ▼
Database
      │
      ▼
Analytics
      │
      ▼
Frontend
```

That separation is incredibly valuable. If EA changes the save format in FC 27 or FC 28, you only need to update the parser that produces the normalized JSON. The import logic, database schema, analytics, and UI can remain almost entirely unchanged. It's a small design decision now that will save you a lot of maintenance work later.
